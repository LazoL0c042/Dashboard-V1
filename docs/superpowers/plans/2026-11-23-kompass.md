# Kompass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Private Mehrbenutzer-Web-App mit Council (8 Rollen, Gratis-Modelle), eingefrorenen Plänen mit Auswertung gegen MSCI World, Recherche, Produktübersicht und Rechner mit historischen Szenarien und deutschen Steuern.

**Architecture:** FastAPI + SQLite im Ordner `kompass/`, Vanilla-JS-PWA ohne Build. Reine Rechenlogik (Szenarien, Steuern, Konsens, Auswertung) in eigenen Modulen ohne I/O, damit testbar. Alles Externe (Modelle, Kurse, Feeds) hinter austauschbaren Funktionen, in Tests durch Fakes ersetzt. Council läuft als Hintergrund-Thread und schreibt Beitrag für Beitrag in die DB; das Frontend pollt.

**Tech Stack:** Python 3.12, FastAPI, uvicorn, httpx, yfinance, sqlite3, pytest; Vanilla JS/CSS.

**Spec:** `docs/superpowers/specs/2026-11-23-investment-tool-design.md`

## Global Constraints
- Ordner `kompass/`; `werkbank/` bleibt unverändert.
- UI-Texte und Kommentare Deutsch.
- Keine Orders, kein Broker-Schreibzugriff. Kein öffentlicher Port (Bind 127.0.0.1, Tailscale serve).
- Jede angezeigte Zahl: Quelle + Datum oder Marker „geschätzt“.
- Pläne und Council-Protokolle unveränderlich (DB-Trigger verhindert UPDATE/DELETE), nur Nachträge.
- Nutzerdaten per `user_id` getrennt; jede Abfrage filtert danach.
- Geheimnisse nur in `.env`; nie loggen.
- Nur kostenlose Dienste. Vergleichswert: iShares Core MSCI World, IE00B4L5Y983, Ticker `EUNL.DE`.
- Konsens: Spanne ≤ 15 Prozentpunkte UND Kritiker `einwand_widerlegt = true`; max. 4 Runden.
- Szenarien: rollierende Fenster, Worst = P5, Realistisch = P50, Best = P95, real (inflationsbereinigt) führend.
- Steuer: 25 % + 5,5 % Soli; KiSt 8/9 % per Formel; Pauschbetrag 1.000/2.000 €; Teilfreistellung Aktien 30 %, Misch 15 %, Anleihen 0 %; Gold/Krypto direkt steuerfrei nach > 1 Jahr.
- `pytest -q` grün vor jedem Commit.

## Review Focus
1. Zu langer Horizont für die Datenreihe (z. B. 60 Jahre Krypto) → klare Meldung, keine erfundenen Szenarien. Test in Task 2.
2. Modell liefert kein gültiges JSON / alle Anbieter im Limit → Lauf endet mit Status `fehler` und lesbarer Meldung, Protokoll bleibt erhalten. Test in Task 5.
3. Nutzer A ruft Plan/Sitzung von Nutzer B per ID auf → 404. Test in Task 4 und 6.
4. Kurs für Ticker nicht abrufbar → Auswertung zeigt „Kurs fehlt“ statt Absturz oder 0 €. Test in Task 6.
5. Verlust im Steuerfall (Endwert < Einzahlung) → Steuer 0, kein negativer Steuerbetrag. Test in Task 3.
